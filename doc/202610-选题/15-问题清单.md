### A2（U2）K=8 截断取的是全局最热门 8 个值

| 字段 | 内容 |
| --- | --- |
| 类别 | 数据侧 bug（必须先修） |
| 现象 | `ENCODE_MAX_LEN = 8`，`_encode_values` 里先 `sorted(set(ids), key=lambda x: (x == OOV_ID, x))` 再把 OOV 排到末尾，随后 `kept = unique[:ENCODE_MAX_LEN]`；而词表 id 是按频次降序分配的，所以取到的是**最热门的 8 个**。08 号记录公共特征表单行的 `feature_count` 是 343、1025，13 个域平摊下来每域几十个取值。对行为序列域 `109_14/110_14/127_14/150_14`（08 点名的高频前四）来说，「最热门的 8 个」几乎人人都有，再经 `embedding.py` 的 masked mean pooling 平均后，不同用户的池化向量高度相似，个性化信号被抹平。`embedding.py` 本身已核对正确（mask、PAD 置零、除零保护都对），问题全在上游截断。 |
| 证据 | `src/data/prepare_aliccp.py`：`ENCODE_MAX_LEN = 8`（52 行）、`_encode_values`（312 行）、`truncated`/`kept = unique[:ENCODE_MAX_LEN]`（336–338 行）；`1386` 行注释也写明「encode 截断时取最小 K 个即高频前 K」。`src/models/embedding.py` 的 masked mean pooling。08 号文档的 `feature_count` 实测。 |
| 验证方法 | 先把 `unique[:ENCODE_MAX_LEN]` 改成 `unique[-8:]`（取最低频/最具区分度的 8 个）跑一次 10% 的 MLP-CVR，CVR AUC 动了即成立。 |
| 影响 | 不改则用户侧特征等于被压成「人人一样」的常量，A1 修好也发挥不出来。改 K 或改 EmbeddingBag 都会改数据格式，同样触发 `20_processed` 重建。 |
| 修复成本 | 三个改法：①`unique[-8:]` 一行，仅用于验证；②K 从 8 调到 32，一行，存储/显存 ×4；③`nn.EmbeddingBag + offsets` 变长池化、不截断，约 50 行，正规做法（会改数据契约）。 |
| 依赖 | 与 A1 同批重建；③还要动 `embedding.py` 与模型侧契约。 |
| 状态 | 待处理 |

## H 根因判断与执行顺序

### H1 暂不能走 R5

R5 的前提是「方法本身没赢」。现在的证据更像「方法还没真正启用」——在下面三个根因排掉之前走 R5，等于把 bug 写成研究结论。

机理链（按因果顺序）：

1. **101 被误剔** → 用户侧特征整体残缺 → 模型整体弱（CVR AUC 0.55）；
2. 特征弱 → 从点击空间外推到曝光空间更不准 → 全空间偏差更大；
3. **detach 让 DR 的 CVR 梯度 ≡ IPS**（11 号笔记记 `max|grad_DR − grad_IPS| = 0`，见 12 号 E34 待落）→ 双重稳健机制没真正参与，两个变体在优化上同构；
4. **IPS + 分位数截断系统性压低低 e 样本权重**，而低 e 样本恰是点击空间里最欠代表的部分 → 欠纠偏 → 全空间残留高估 → `Bias vs p* = 0.252` 最大。

反证：ESMM 不做加权，pCVR 被 CTCVR 乘积约束，反而 `0.068`，比本方法好。

对外口径参照：Ali-CCP 上 ESMM、ESCM² 原文及常见复现的 CVR AUC 在 **0.65–0.68**，本项目最高 **0.5527**，差约 0.10，是 04 号 R2 判据（「差超过 0.02 且无法解释」）的 5 倍；而合成数据冒烟能到 **0.751–0.777**，说明建模链路本身会学，掉到 0.55 指向**特征或数据**，不是结构。

### H2 结论

先修数据，再谈口径，最后才谈方法输赢。**当前正在跑的 P0 detach 对比（9 runs）建立在坏特征上，结论不能作为口径依据。**
