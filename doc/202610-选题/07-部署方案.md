# 部署方案

> 部署在本项目里不是「上线赚流量」，而是**答辩时能现场演示、且结果可重放**。因此只保留三条线：开发机跑通、训练机产出、演示环境起一个只读推理服务。
> 对应总案第 8 节；对应目录 `deploy/`。

## 1. 三条部署线

| 线 | 在哪 | 干什么 | 出口 |
| --- | --- | --- | --- |
| A 开发 | 自己的 Windows + CPU | 跑单测、合成数据冒烟、改代码 | `pytest` 30 项全绿 |
| B 训练 | 实验室 GPU 或 WSL2 | 全量 Ali-CCP、6 个模型配置 × 5 种子 | `artifacts/runs/<exp>/<model>_<loss>/seed<k>/metrics.json` |
| C 演示 | 本机 Docker Compose（Docker 在 WSL2 内） | 起一个只读推理服务，浏览器/curl 调 | `http://localhost:8000` |

A 与 B 共用同一份代码和配置；C **只读产物**，不训练、不读原始数据。这条边界决定了演示环境可以很小。

## 2. 产物规范（部署的唯一输入）

```
artifacts/
├─ models/uc_escm_seed0.pt          # state_dict
└─ runs/main/uc_escm/seed0/
   └─ metrics.json                  # 必须含 config（含 field_dims）与 calibration（T/tau/alpha）
```

服务启动时只认 `metrics.json`：没有它就无法知道 `field_dims` 和模型名，直接拒绝启动并打印缺什么。`calibration` 缺失时退化为 `T=1`（不校准），并在 `/meta` 里如实体现。

## 3. 端到端流程

### 步骤 0：环境基线

```bash
python --version                     # 3.12.x
pip install -r requirements.txt      # 训练侧依赖
pip install fastapi "uvicorn[standard]"   # 服务侧依赖（见 deploy/requirements.txt）
```

### 步骤 1：产出模型

```bash
python -m src.train exp=main data=aliccp model=uc_escm loss=vrdr train.seed=0
```

训练结束会同时落 `artifacts/models/uc_escm_seed0.pt` 与 `metrics.json`，后者是部署的契约文件。

### 步骤 2：产物自检（不通过就不许部署）

```bash
python -c "import json,torch;m=json.load(open('artifacts/runs/main/uc_escm/seed0/metrics.json'));\
print(m['metrics']['calibration']);torch.load('artifacts/models/uc_escm_seed0.pt',map_location='cpu')"
```

三条必须成立：`config.data.field_dims` 存在、`metrics.calibration` 有 `temperature/tau/alpha`、`state_dict` 能 load 且键名与当前代码一致（改过模型结构就要重训，不能复用旧 ckpt）。

### 步骤 3：本机起服务（不用 Docker 也能演示）

```bash
RUN_DIR=artifacts/runs/main/uc_escm/seed0 \
  python -m uvicorn deploy.serve:app --host 127.0.0.1 --port 8000
```

Windows PowerShell 写法：

```powershell
$env:RUN_DIR="artifacts/runs/main/uc_escm/seed0"; python -m uvicorn deploy.serve:app --port 8000
```

### 步骤 4：打镜像

```bash
docker build -f deploy/Dockerfile -t cvr-debias-api:0.1 .
```

要点：依赖先装、代码后拷（改代码不重装依赖）；推理镜像只装 `deploy/requirements.txt`（不含 pandas/pyarrow/pytest）；torch 走 `download.pytorch.org/whl/cpu`，镜像比默认源小很多。

### 步骤 5：Compose 起服务

```bash
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml ps          # 等 health 变 healthy
docker compose -f deploy/docker-compose.yml logs -f api
```

模型产物以**只读卷**挂载（`../artifacts:/app/artifacts:ro`），不烤进镜像——同一个镜像可以切不同种子/模型做对比演示。

### 步骤 6：切换与回滚

```bash
# 换模型：只改 RUN_DIR，不重建镜像
RUN_DIR=artifacts/runs/main/esmm/seed0 docker compose -f deploy/docker-compose.yml up -d

# 回滚：把 RUN_DIR 指回上一版产物目录，容器重启即可
```

镜像本身带 `cvr-debias-api:0.1` 标签，回滚镜像用 `:0.0` 标签 + 同一份产物目录。

### 步骤 7：收工归档

演示前把 `artifacts/runs/` 与 `doc/tables/` 一起打包（体积小、可重算），原始数据不进包（合规要求见 06 文档）。

## 4. 接口契约

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/healthz` | — | `{"status":"ok","model":"uc_escm"}` |
| GET | `/meta` | — | 模型名、`field_dims`、`n_fields`、校准参数、ckpt 路径 |
| POST | `/predict` | `{"ids": [[23 个 int], ...]}` | `{"p_ctr":[...],"p_cvr":[...],"p_ctcvr":[...]}` |

约定：

- `ids` 每行长度必须等于 `len(field_dims)`，取值 `0 ≤ id < field_dim`；越界返回 **422** 并指出第几列、上限多少；
- 单批上限 2048 行，超限 **413**；
- 只有 CVR 模型（`mlp_cvr`）时 `p_ctr` / `p_ctcvr` 返回 `null`，不伪造；
- `p_ctr` 输出的是**校准后**的概率（`sigmoid(logit/T)`），`p_ctcvr = p_ctr × p_cvr`，与训练侧 `evaluate` 的口径一致。

```bash
curl -s -H "Content-Type: application/json" \
  -d '{"ids":[[10,20,30,40,50,1],[199,199,199,119,59,29]]}' \
  http://127.0.0.1:8000/predict
```

## 5. 验收清单

| 检查 | 通过标准 |
| --- | --- |
| `/healthz` | 200 且 `model` 与产物一致 |
| `/meta` | `n_fields == len(field_dims)`，`calibration` 三项齐全 |
| `/predict` | 三数组长度相同，`p_ctcvr[i] == p_ctr[i]*p_cvr[i]`（误差 < 1e-12） |
| 越界/超批 | 分别返回 422 / 413，进程不崩 |
| 容器 | `ps` 显示 healthy；`docker stats` 内存 < 1.5 GB（实测 175 MB） |
| 重启 | `restart` 后 20 秒内 healthy（模型加载秒级，其余等健康检查间隔） |

## 6. 资源与端口

| 项 | 值 |
| --- | --- |
| 端口 | 8000（宿主与容器一致） |
| 内存 | 实测 175 MB（CPU 版 torch + 小模型） |
| 镜像 | 实测 1.56 GB（cpu wheel + slim 基础镜像） |
| 启动时间 | 容器启动秒级，`healthy` 在 20–30 秒内（受健康检查间隔影响） |

端口冲突就改 compose 的 `ports` 左侧（如 `"8010:8000"`），服务内部端口不变。

## 7. 常见故障

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 启动即退出，提示找不到 `metrics.json` | `RUN_DIR` 没传或路径错 | 传绝对路径；容器内路径必须以 `/app/artifacts` 开头 |
| `load_state_dict` 报 missing/unexpected keys | 改过模型结构但复用旧 ckpt | 重训，不允许改代码配旧权重 |
| 422 报「第 j 列越界」 | 前端/调用方用了全量词表 id | 用训练时 `vocab.json` + `field_dims` 对齐 |
| 镜像构建卡在 torch | 默认源下载慢 | 确认 `deploy/requirements.txt` 里的 cpu extra-index 生效 |
| 容器 healthy 但 `/predict` 502 | 端口映射错 | 检查 `ports` 左值，容器内始终 8000 |
| Windows 下 `RUN_DIR=... python ...` 不生效 | PowerShell 不认前置环境变量 | 用 `$env:RUN_DIR="..."` 再执行 |

## 8. 答辩演示拓扑

```
浏览器 / curl
     │  HTTP :8000
     ▼
[ api 容器 ]  ──只读挂载──▶  artifacts/（ckpt + metrics.json）
     │
     └─ /healthz  /meta  /predict

旁边再开一个终端跑 python -m pytest → 30 passed
```

一句话讲清：**服务是壳，结论在 artifacts 里**；演示时先放 `/meta`（证明加载的是哪次训练），再放 `/predict`（证明能出三级概率），最后切 `RUN_DIR` 换模型对比。

## 10. 本机环境处理

**① 环境变量**：Docker Desktop 是当前用户安装，可执行文件在
`C:\Users\<用户名>\AppData\Local\Programs\DockerDesktop\resources\bin`，安装器已写入**用户 PATH**。
注意：安装前就打开的终端读不到新 PATH，需新开终端；Trae 内置终端若仍报 `docker 不是内部或外部命令`，先重启 IDE 或在该终端临时前置：

```powershell
$env:Path = "C:\Users\<用户名>\AppData\Local\Programs\DockerDesktop\resources\bin;$env:Path"
```

**② 镜像加速**：`%USERPROFILE%\.docker\daemon.json`

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ],
  "builder": { "gc": { "defaultKeepStorage": "20GB", "enabled": true } },
  "features": { "buildkit": true }
}
```

改完用 `docker desktop restart` 或右键托盘「Restart」生效，用 `docker info | findstr -i mirror` 核对。

**③ 从零构建很慢，优先复用镜像**：本网络下 `download.pytorch.org` 实测仅 155 KB/s、阿里云 PyTorch 镜像 393 KB/s，209 MB 的 torch CPU wheel 要 9–22 分钟，构建常被判为"卡住"。已验证的绕法是复用 WSL 里已构建好的镜像：

```powershell
$env:Path = "C:\Users\<用户名>\AppData\Local\Programs\DockerDesktop\resources\bin;$env:Path"
wsl -d Ubuntu -u root -- docker save cvr-debias-api:0.1 -o /mnt/e/cvr-debias/deploy/_image.tar
docker load -i E:\BISHE\deploy\_image.tar
docker compose -f deploy/docker-compose.yml up -d --no-build
```

**④ 启动 Docker Desktop 的方式有讲究**：从自动化终端用 `Start-Process` 直接拉起，进程会随该终端退出并被回收（表现为"引擎 running 但 `\\.\pipe\dockerDesktopLinuxEngine` 不存在"）。要用资源管理器分离启动：

```powershell
Start-Process explorer.exe -ArgumentList '"C:\Users\<用户名>\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe"'
```

**⑤ 默认 `RUN_DIR` 已改为冒烟产物** `artifacts/runs/smoke/uc_escm/seed0`，`compose up` 开箱可用；真实训练完成后改成 `artifacts/runs/main/<model>/seed0`。
