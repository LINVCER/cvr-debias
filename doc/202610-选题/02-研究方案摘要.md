# 研究方案摘要

> 本文档是论文第 3–5 章的技术底稿，也是代码实现的口径来源。公式与实现必须逐条对齐。

## 1. 问题形式化

记一条曝光样本为三元组 (x, y, z)：x 为特征，y ∈ {0,1} 为点击，z ∈ {0,1} 为转化。曝光集合 D，点击子集 O = {i : y_i = 1}。三个概率量满足乘法分解：

```
P(y=1, z=1 | x)  =  P(y=1 | x)  ·  P(z=1 | y=1, x)
      pCTCVR            pCTR            pCVR
```

**本数据上的量级**（Ali-CCP train，清洗后）：曝光 42,300,135 → 点击 1,644,256（3.887%）→ 转化 8,802（0.535%），CTCVR 0.0208%。两级分别收缩约 25.7 倍与 187 倍，合计约 4800 倍。这是 DS 的量化含义，也是「从点击空间退到曝光空间」的直接动机。

转化标签 z 仅在 y = 1 时可观测。令观测指示 o_i = y_i，倾向得分 e_i = P(o_i = 1 | x_i) = pCTR_i：

```
L_ideal = (1/|D|) Σ_{i∈D} δ(ẑ_i, z_i)
L_naive = (1/|O|) Σ_{i∈O} δ(ẑ_i, z_i)        # 有偏（MNAR）
L_IPS   = (1/|D|) Σ_{i∈D} o_i δ_i / e_i
L_DR    = (1/|D|) Σ_{i∈D} [ δ̂_i + o_i (δ_i − δ̂_i) / e_i ]
```

IPS 在 e 正确时无偏；DR 在 e 或 δ̂ 任一正确时无偏。全部技术动作都落在 e_i 与 δ̂_i 上。

## 2. UC-ESCM（本科版 = C1 + C2，C3/C4 进展望）

### 2.1 结构

四层、三塔、四项损失：

| 层            | 内容                                                          |
| ------------ | ----------------------------------------------------------- |
| 共享特征层        | 23 个稀疏域一张 embedding 表（维度 16）。稀疏场景下共享 embedding 是知识迁移主通道，不拆分 |
| 解耦专家层（C3，展望） | 专家池划为倾向专属 / 转化专属 / 共享三组，门控掩码隔开；本科保留结构，不做主实验                 |
| 任务塔层         | CTR 塔输出 ê、CVR 塔输出 ẑ、插补塔输出 δ̂（**不与 CVR 塔共参**）                |
| 因果损失层        | 校准模块把 ê 转为可用于加权的 ẽ，组装四项损失与正交正则                              |

读图的关键：**校准后的倾向得分只作为权重进入损失，不回传梯度**。

### 2.2 目标函数

```
L = Σ_{k∈{ctr,cvr,ctcvr,imp}} ( 1/(2σ_k²) · L_k + log σ_k ) + λ_orth · R_orth
```

**校准倾向（C1）**：CTR 塔 logit 记为 s_i，温度 T 在验证集上最小化 NLL 拟合，截断点 τ 取训练集 pCTR 的 α 分位数：

```
ẽ_i = max( τ, σ(s_i / T) ),   τ = Quantile_α( { σ(s_j / T) }_{j∈D} )
```

α 在 {0.001, 0.005, 0.01, 0.05} 上选择，准则是验证集上**校准误差与 1/ẽ 权重方差的加权和**，而不是 AUC。这是与「固定 clip 阈值」的关键区别。

**方差正则双重稳健（C2）**：

```
L_cvr = (1/|D|) Σ [ δ̂_i + o_i (δ_i − δ̂_i) / ẽ_i ]
L_imp = (1/|O|) Σ (1 − ẽ_i)/ẽ_i² · (δ_i − δ̂_i)²
```

加权形式源于 MRDR（SIGIR 2021），**不是本研究原创**。本研究贡献是把点击空间的加权推广到全空间 ESCM² 框架，并与校准倾向联合分析（这对应命题 P1 与 P2/P3）。开题与论文必须按这个口径表述。

**正交正则（C3，展望）**：

```
R_orth = ‖Z_pᵀ Z_c‖_F² / (B · n_p · n_c),   Z 为按列标准化后的专家输出
```

目的是让 CTR 梯度不再直接塑造 CVR 表征，对应 ESCM² 的潜在独立优先（PIP）。

实测结论：**主实验必须关掉它**（`orth_lambda: 0.0`）。λ=0.1 时 CTR 头均值完全学不出来（AUC 0.16、温度贴到上界 20）；λ=0.01 仍会压制均值（CTR PCOC ≈ 11）。原因是标准化放大了低方差列的梯度，正则项量级（约 0.3–0.8）与任务损失同量级，λ 名义上很小、梯度上并不小。要真正用 C3，需要用 GradNorm 式的损失尺度自适应，这属于展望章的内容。

### 2.3 三个待验证的命题（本科：文字论证 + 数值验证）

| 命题         | 表述                                                  | 证明思路 / 验证方式                                         |
| ---------- | --------------------------------------------------- | --------------------------------------------------- |
| P1 双重稳健性保持 | 若 ẽ = e 或 δ̂ = δ，则 L_cvr 是 L_ideal 的无偏估计；方差正则不破坏该性质 | 展开两项期望求交叉项；`tests/test_dr_unbiased.py` 数值验证         |
| P2 截断偏差上界  | 截断引入的额外偏差 ≤ P(e < τ) × δ_max                        | 对 e_i < τ 的样本逐项界定；τ 为分位数时 P(e < τ) ≤ α，得到与 α 线性的显式界 |
| P3 方差有界性   | 未截断 DR 方差在 e → 0 时无界；截断后方差 ≤ δ²_max / τ             | 逐样本方差求和，结合 P2 得到偏差–方差权衡关于 α 的单峰形式                   |

P2 + P3 = 「为何存在最优 α」。若一般条件下证明困难，降级为在有界损失（裁剪交叉熵）假设下给出，并在论文中明写假设。

### 2.4 与现有方法的退化关系（直接进方法章）

| 参数设置                                           | 退化为            |
| ---------------------------------------------- | -------------- |
| T = 1, α = 0, λ_orth = 0, 权重固定, L_imp 换回普通 MSE | ESCM²-DR       |
| 进一步去掉插补塔（δ̂ ≡ 0）                               | ESCM²-IPS      |
| 再令 ẽ ≡ 1 并保留全空间 CTCVR 项                        | MMoE 结构上的 ESMM |
| 只保留点击空间的 L_cvr                                 | 朴素 CVR         |

这张表是论文「框架普适性」的最低成本写法，也是消融设计依据。

## 3. 实现上的三个坑

1. **ẽ 必须 detach**。倾向得分作为权重进入 CVR 损失时不能回传梯度，否则模型会学会把 pCTR 推高来转化器损失。这是复现 ESCM² 最常见的错误。
2. **温度 T 是后验拟合，不进主训练图**。训练完 CTR 头后在验证集单独拟合，否则会与分类损失相互抵消。**只用普通 NLL，不要按负正比加权正样本**：实测在合成数据上（点击率 4.3%、原始 pCTR 均值 0.0458）普通 NLL 给出 T≈0.96，校准前后均值一致；按负正比加权后 T 被拉到 5.57、预测均值升到 0.23、PCOC 从 1.0 变成 5.6。原因是温度标度只能调整分布形状，无法纠正均值，一旦把均值偏差引进来，校准就被破坏。
3. **四项损失尺度差异极大**（CTCVR 正样本率仅 0.021%）。不确定性加权里的 log σ_k 要用 log_var 参数化并初始化为 0，否则前几百步数值溢出。

另有一个必须做消融的实现选择：`dr_loss` 里的 imp 是否 detach。ESCM²-DR 是联合训练（不 detach），DR-JL 系列是交替训练。两种都跑，结果写进论文，这是免费的一个子发现。

## 4. 数据工程

### 4.1 Ali-CCP 预处理七步

1. **下载与校验**：记录文件大小与 md5，写入 `data/MANIFEST.md`；
2. **流式解析 + join**：先把公共特征表建成磁盘字典（LMDB 或按 index 分桶 Parquet），再流式扫骨架表逐条 join，**切勿两表全载入内存**；
3. **特征域选定**：23 个稀疏域——用户侧 101 / 109_14 / 110_14 / 127_14 / 150_14 / 121 / 122 / 124 / 125 / 126 / 127 / 128 / 129，商品侧 205 / 206 / 207 / 210 / 216，组合 508 / 509 / 702 / 853，上下文 301；以实际文件出现的 field id 为准，缺失域在论文中说明；
4. **词表**：按域统计频次，频次 < 5 归 OOV；**词表只能用 train 统计**，test 新值一律进 OOV；
5. **编码落盘**：int32 + Parquet 分片，每片约 200 万行，标签单独存 click / conversion；
6. **划分**：test 原样；train 切 5% 作验证集（必选项）；
7. **统计产出**：`stats.json` 记录各域基数、标签率、pCTR 分位数，直接生成论文表 1 与图 2。

10% 采样集按**用户 ID 哈希**采样（不是行级随机），用于调参与开发自测。

**引用纪律**：论文表 1 的所有统计量必须由自己的 `stats.py` 输出，引用数据集页面的二手数字是答辩常见扣分点。

### 4.2 半合成偏差基准（C5）

1. 在 Ali-CCP 点击样本上训教师 CVR 模型 f\*，对全部曝光输出 p\*(x) 作为伪真值，采样得全标签集 D_full；
2. 日志策略 π_β(x) = σ(β·g(x) + b)，g 与 p\* 正相关；β = 0 为完全随机暴露，β 越大 SSB 越强；b 二分求根，把整体点击率钉在 4%，保证不同 β 可比；
3. 按 π_β 采样观测指示 o，仅 o = 1 时暴露 z，得到有偏训练集；
4. 评估回到 D_full，直接算 Bias = E[ẑ − p\*] 与 MSE；
5. β ∈ {0, 0.5, 1, 2, 4}，画「偏差强度–方法表现」曲线。

**必须写进论文的局限**：伪真值来自模型，带教师模型自身偏差。半合成结果只用于方法间相对比较，绝对数值不作结论。主动写清比被审稿人指出好得多。

基准正确性自检：β = 0 时朴素 CVR 与纠偏方法的偏差应接近，β 增大时差距应单调扩大；不满足说明构造有错，先修基准。

## 5. 大数据技术栈（本科必做）

Ali-CCP 的骨架表与公共特征表 join 本身就是真实的大数据任务——八千多万行、单机 Pandas 做不了。不需要人造场景，把这个理由写清即可。

### 5.1 Hive 分层表

| 层   | 表                           | 内容                       | 分区       |
| --- | --------------------------- | ------------------------ | -------- |
| ODS | `ods_aliccp_skeleton`       | 骨架表原始落地，不做加工             | split    |
| ODS | `ods_aliccp_common_feature` | 公共特征表原始落地                | split    |
| DWD | `dwd_aliccp_sample`         | join 后的曝光明细宽表，特征串解成 23 列 | split    |
| DWS | `dws_aliccp_vocab`          | 各域取值频次与编码索引              | field_id |
| ADS | `ads_aliccp_train`          | 编码后的训练样本（整数数组 + 双标签）     | split    |

**存储格式取舍**（要写进论文）：ODS 与 DWD 用 ORC + Snappy（Hive 原生最优），ADS 改 Parquet，因为下游是 PyTorch 的 pyarrow 读取。解释清这一句取舍，比堆组件名更有说服力。

### 5.2 Spark 原生算子解析特征串

```
SEP_ITEM, SEP_FIELD, SEP_W = chr(1), chr(2), chr(3)   # 实测值，见 08-数据探测记录.md
# 特征串结构： field_id <02> value <03> weight，特征之间用 <01>

parsed = (sample
    .withColumn("kv", F.explode(F.split(F.col("feat_list"), SEP_ITEM)))
    .withColumn("field_id", F.split(F.col("kv"), SEP_FIELD).getItem(0))
    .withColumn("rest", F.split(F.col("kv"), SEP_FIELD).getItem(1))
    .withColumn("feat_val", F.split(F.col("rest"), SEP_W).getItem(0))
    .withColumn("w", F.split(F.col("rest"), SEP_W).getItem(1).cast("float")))

w = Window.partitionBy("field_id").orderBy(F.desc("cnt"))
vocab = (parsed.groupBy("field_id", "feat_val").agg(F.count("*").alias("cnt"))
    .where(F.col("cnt") >= 5)
    .withColumn("idx", F.row_number().over(w)))
```

不用 Python UDF：避开序列化开销，配一张「UDF 对比原生算子耗时」的图，就是属于大数据专业的小贡献，成本极低。

### 5.3 四项调优（都要写进论文）

1. `spark.sql.shuffle.partitions` 按数据量设，默认 200 对八千万行偏小；
2. 热门商品 ID 导致 groupBy 倾斜，开 AQE（`spark.sql.adaptive.enabled` 与 `skewJoin.enabled`），贴 Stage 耗时对比图；
3. ADS 写出前 repartition 控制单文件 128–256 MB，避开小文件问题；
4. 只取必要列，在 Spark UI 的 scan 行数里验证谓词下推与列裁剪生效。

### 5.4 运行环境三档

| 档       | 环境                         | 论文里能写什么                                         |
| ------- | -------------------------- | ----------------------------------------------- |
| 单机      | `spark local[*]`           | 「用了 Spark」成立，但没有分布式证据，属最低要求                     |
| 伪分布（推荐） | Docker 1 master + 2 worker | 可截 Spark Web UI 的 Stage / Shuffle / 倾斜详情，有真东西可写 |
| 云上      | 按量 EMR                     | 可做横向扩展实验：1 / 2 / 4 节点对比预处理耗时                    |

横向扩展实验（节点数 vs 耗时 + 加速比曲线）是本专业最容易拿分的一张图，成本几小时按量费用。

## 6. 评估协议

- 指标唯一实现（`src/evaluation/metrics.py`），全部写 `metrics.json`，绝不在各模型脚本里各写一份；
- 每配置 5 种子，报 mean ± std，不报单次最优；
- 与最强基线做配对双尾 t 检验（α = 0.05），多重比较用 Holm-Bonferroni 校正；
- 主指标额外给 bootstrap 置信区间（1000 次重采样），比 t 检验更难被质疑；
- 早停轮数、温度 T、截断 α、权重全部在验证集上定。
