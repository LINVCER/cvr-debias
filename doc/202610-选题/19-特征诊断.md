### 3.2 截断保留的是不是「全局最热门」

**是，而且是代码层面的确定性行为**：`_encode_values` 先按词表 id 升序排序（`sorted(set(ids), key=lambda x: (x == OOV_ID, x))`），再取前 32（[prepare_aliccp.py](file:///e:/BISHE/src/data/prepare_aliccp.py#L338-L341)）。词表 id 按曝光加权频次降序分配，所以「取前 32」= 「取该行里全局最热门的 32 个值」，与行内权重、时间顺序、用户偏好无关。

### 3.3 个性化信号是否被抹平

对 10,000 个随机用户（uid % 13 == 0，共 311,371 行）做池化：集合 = 该用户所有行里出现过的真实 id；再与「按同一 id 边缘分布独立重抽同样大小的集合」做基线对比。

| 指标 | 109_14 | 110_14 | 127_14 | 150_14 |
| --- | ---: | ---: | ---: | ---: |
| 每用户池化集合大小（均值） | 55.2 | 60.8 | 59.4 | 63.4 |
| 跨用户平均余弦 | 0.2140 | 0.0159 | 0.0641 | 0.0730 |
| **同用户（行奇偶两半）平均余弦** | **1.0000** | **1.0000** | **1.0000** | **1.0000** |
| 全局随机基线余弦 | 0.1965 | 0.0209 | 0.0744 | 0.0781 |
| 同用户行对平均 Jaccard | 0.989 | 0.989 | 0.988 | 0.997 |
| 跨用户行对平均 Jaccard | 0.1918 | **0.0135** | 0.0581 | 0.0541 |

读法：

1. **行内去重 0.898–0.992**（P50/P90 均为 32/32）：每行确实有远多于 32 个候选值，截断几乎总在生效。
2. **同用户余弦恒为 1.0000、同用户行级 Jaccard 0.988–0.997**：一个用户所有行截断后的取值集合几乎是同一套。序列表征在**用户内是常量** —— 只能贡献一个用户级偏置，无法给同一用户的不同候选商品排序（而 CTR 排序恰恰需要在用户内区分商品）。
3. **跨用户余弦不高于「按全局边缘分布重抽」的基线**（110_14 0.0159 vs 0.0209；109_14 0.2140 vs 0.1965 基本持平）：不同用户之间并没有共享同一套「全局最热 32」，各用户的集合互不重叠。所以**不是**「所有用户都被压成同一组热词」，而是「每个用户被压成自己的一组常量」。
4. 结论：截断丢掉的是**页内信息**（时间序、原始 `weight`、最近行为），留下的是用户级常量画像；它与 101（用户 ID）高度冗余，而 101 本身 OOS 也只有 0.5003。这解释了 4 个序列域单域 OOS 为何只有 **0.5103–0.5146**。

## 4. 结论

### 4.1 哪些是死特征

- **低基数商品域（9 个）**：121(99)/122(15)/124(4)/125(9)/126(5)/127(5)/128(4)/129(6)/301(5)，OOS AUC 0.5003–0.5114，命中率 41%–100% 但取值太少，等价于常数/准常数。
- **稀疏商品域（2 个）**：509（命中 21.20%）、702（22.08%），OOS 0.5127/0.5171；853 命中 41.06% 但仍有 0.5432，不能算死。
- **4 个序列域**：109_14 / 110_14 / 127_14 / 150_14，OOS 0.5103–0.5146。§3 证明截断后它们在同一用户内是常量（池化余弦 1.0000、行级 Jaccard 0.988–0.997），只剩用户级偏置，不能提供页内排序信息。
- **半死**：205（OOV 8.87%，内样本 0.7176 / OOS 0.5316，只记忆不泛化）；101（OOS 0.5003，99.58% 未见，模型里只会贡献记忆）。

净结果：23 个域里真正带泛化信号的只有 **6 个商品域**（206/508/210/853/216/207）。

### 4.2 哪个环节把 CTR AUC 压到 0.549

把同一把尺子放在一起。注意：模型指标落在 **test**（与 train 共享 47.03% 用户），我的两条基线分别给 val 与用户不交叉的奇偶 OOS 两个口径：

| 方案 | AUC（test / val，含用户重叠） | AUC（奇偶 OOS，用户不交叉） |
| --- | ---: | ---: |
| ESMM 30 epoch（17 号 §13，test 4.30M 行） | 0.5490 | — |
| 单个最强域 206 的边际目标编码 | 0.5572（val） | 0.5596 |
| 5 个强商品域（206/508/210/853/216）加性组合 | **0.5695**（val） | **0.5691** |
| 6 个强商品域（+207）加性组合 | 0.5691（val） | 0.5682 |
| 22 域加性组合（不含用户记忆 101） | 0.5712（val） | 0.5676 |

1. **特征侧够用**：不需要交互、不需要 embedding，光是 5 个商品域的边际目标编码就 OOS 0.5691（val 0.5695）；22 域全加 0.5676。特征里存在 0.57 量级、可跨用户泛化的信号。
2. **模型没吃到**：30 epoch 的 ESMM 只有 0.5490，**低于单域 206 的用户不交叉口径 0.5596，也低于 6 域加性的 0.5682**。一个有 23 域输入、81M embedding 参数的模型，跑不过「一个商品域 + 一张查表」。
3. 因此瓶颈不在「特征不够」，而在 **表征/建模环节**：23 域各自 masked-mean 池化后拼成 368 维，再进 (64,32) 的小塔（[embedding.py](file:///e:/BISHE/src/features/embedding.py#L36-L55)、[baselines.py](file:///e:/BISHE/src/models/baselines.py#L25-L42)）。它既没有把 206/508/210 这类单值域的 ID 边际直接变成加性 logit，也没有为 4 个序列域提供任何有效变换（这 4 个域贡献的是 4×16 维**用户级常量**，对排序无信息）。这与 §13「加 epoch 不涨、T 飙升、ECE 恶化」的现象吻合：模型在拟合噪声与偏置，而不是在学商品侧的边际排序。
4. 另一个必须修的统计口径：**val 与 train 共享 85.71%、test 共享 47.03% 用户**，0.5490 里含用户记忆。后续门槛必须落在用户不交叉的切分上，否则会被泄漏抬高（加性模型加 101 就从 0.5712 跳到 0.5816）。

### 4.3 候选改动（只提方案，按性价比排序）

1. **给单值商品域加一条 wide/线性通路（最低成本，预期收益最大）**
   对 206/508/210/853/216/207 这 6 个域，除 embedding 外再各加一个「id → 标量 logit」的线性项（或 field-wise FM 一阶项），直接与深塔输出相加。它们单独 OOS 0.5384–0.5596、6 域加性 0.5682，这条通路能让模型至少不劣于单域查表；不需要改数据、不需要重编码，只动模型与配置。
2. **按域基数分配 embedding 维度 + 放大塔宽（低成本，可与 1 同时做）**
   现在 23 域统一 16 维、塔 (64,32)。206 只有 7,625 个值却和 110_14 的 242 万值同维；建议高基数域（110_14/205/127_14）降到 8 维并加频次分桶，低基数强信号域提到 32 维，塔改为 (256,128)。仍只需改配置，可先跑 8 epoch 看 CTR AUC 是否离开 0.549。
3. **重做序列编码（成本最高，只有前两条无效时才做）**
   目前 `sorted by global id` 取前 32 等价于「截断到全局最热」，§3 已证明它把页内信号抹平（同一用户所有行的取值集合余弦 1.0000、行级 Jaccard 0.99）。可行方向：截断改按行内权重（原始 `weight` 字段，当前在 L1 被丢弃）排序、或按时间最近取 K；池化从 masked-mean 改为 attention（DIN 式，target 用候选商品）。这条要改预处理与词表，成本高，且在未验证「未截断序列确实更强」之前不建议先做。

### 4.4 报告级结论（可直接引用）

1. 特征不是瓶颈：不需要交互、不需要 embedding，5 个商品域（206/508/210/853/216）的边际目标编码在**用户不交叉**的奇偶 OOS 上就有 **0.5691**，6 域 0.5682，22 域 0.5676。
2. 模型是瓶颈：ESMM 30 epoch 在 test 上 **0.5490**，低于单域 206 的 OOS 0.5596 与 6 域加性的 0.5682；23 域输入、81M embedding 跑不过「一个商品域 + 一张查表」，问题在 masked-mean 拼 368 维 → (64,32) 塔这条表征通路。
3. 23 个域里只有 6 个商品域带泛化信号（206/508/210/853/216/207），其余 17 个 OOS 均在 0.500–0.517；4 个序列域 0.5103–0.5146。
4. 序列域在 K=32 下已被压成**用户级常量**：同一用户任意两行的取值集合余弦 1.0000、行级 Jaccard 0.988–0.997，跨用户相似度不高于随机重抽基线；截断按词表 id 升序取前 32 等价于取全局最热值（110_14 只保留 12.3% 的值），页内信号（时间序、weight、最近行为）全部丢失。
5. 评测口径有缺陷：`val` 与 train 共享 85.71% 用户、`test` 共享 47.03%，0.5490 与任何 AUC 门槛都必须改到用户不交叉切分上复测。
