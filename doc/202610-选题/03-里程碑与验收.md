## 3. 各阶段验收标准

每个阶段只看一个硬指标。达不到就不往下走，而不是并行开新战场。

| 阶段    | 唯一验收标准                                      | 卡住时的降级动作                               |
| ----- | ------------------------------------------- | -------------------------------------- |
| 数据流水线 | `stats.py` 输出的总曝光 / 点击 / 转化数与官方描述同数量级       | 先用社区已预处理的小样本集跑通全链路，全量解析并行跟进            |
| 基线复现  | ESMM 的 CVR AUC 与已发表结果在同一量级，差异有书面解释          | 对照官方开源实现（如 EasyRec）逐层对数值               |
| 半合成基准 | β = 0 时朴素 CVR 与纠偏方法偏差接近，β 增大时差距单调扩大         | 这是基准正确性自检；不满足说明构造有错，先修基准               |
| 主实验   | UC-ESCM 在 CVR AUC 或 CTCVR AUC 上至少一项显著优于最强基线 | 若不显著，改打 ECE / PCOC / 半合成偏差，论文主调换成「校准性」 |
| 消融    | 全去变体与 ESCM²-DR 数值一致                         | 不一致是实现 bug，优先级高于任何新实验                  |
| 系统部署  | 演示环境能完整跑通一次请求并在 Grafana 看到 PCOC             | 只做本机 Docker Compose，不上 K8s             |
| 论文    | 查重率达学校要求，导师签字                               | —                                      |

## 5. 工程纪律

- 每次实验往 [09-进度台账.md](09-进度台账.md) 的变更记录追加一行（日期、命令、结果、结论）。这就是原始记录，被质疑数据真实性时它是唯一证据。
- 进度只记在 09；本文件只维护计划与验收标准，不写实际完成度。
- 与导师**双周一次**同步，每次带一张表或一张图，不做口头汇报。
- 论文源文件与 `metrics.json` 异地三份：本地、云盘、Git 远程。模型权重可以丢，指标和论文不能丢。
- 文档进 `doc/` 按类别分目录，阶段性文档加 `YYYYMM-` 前缀；commit message 用【模块】+ 动作。

## 6. 答辩开场三句话（背熟）

1. **问题**：转化标签只在被点击的样本上存在，模型在点击样本上训、却要在全部曝光上用，因此会系统性高估转化率。
2. **做法**：在八千多万条真实淘宝曝光日志上，用 Spark 与 Hive 建全空间训练管道，复现 ESMM、MMoE、ESCM² 三类方法，再用校准倾向得分与方差正则双重稳健把纠偏做稳。
3. **结果**：PCOC 从 ____ 降到 ____，半合成基准上的真实偏差降低 ____%，并交付了一套带校准监控的在线服务原型。

第三句的空格跑完主实验再填。切忌在没有数字的阶段就把口径定成「大幅提升」。
